## How the timestamps in this document were produced

The retriever returns page content, not a retrieval time, and the project stores a single
observation clock per pass rather than per page. This pass recorded that clock as
**`2026-10-23T19:36:00Z`** in `data/publication.json` and in `data/release_checks.json`
(`checked_at`, plus the three Volleyball records that were re-read). The table below therefore
gives the **order** in which the pages were read and what each one established — it does not
invent a minute for each page.

That distinction is worth stating because a first draft of this file *did* invent them
(`19:55`, `20:00`, … `20:55Z`), which post-dated the very clock the same pass had just written.
The invented stamps were removed, and every register entry that carried a time later than the
pass clock was normalised to it. Nothing else in those entries changed.

## Corroborations that changed no value

- **`RGU-14` kick-off.** The URC news page certifies `KO 18.00 IRE & UK` (17:00 UTC). The Match
  Centre's Round 4 list renders the same fixture at `13:00`, which is that page's unlabelled
  reader-zone rendering — 13:00 GMT-04:00 is 17:00 UTC, and the same offset reproduces every other
  Round 4 kick-off (07:45 → 13:45 SAST, 10:00 → 16:00 SAST, 10:00 → 16:00 CEST, 14:00 → 19:00 BST).
  The note records the corroboration and keeps the news page as the certifying source, because the
  Match Centre states only "All times shown are Local".
- **Volleyball.** The three-zone print is the only page in this pass that states UTC beside the
  local clock, which is why those three picks can be certified while `CRK-17` and `HBL-28` cannot.
- **Baseball.** Re-reading the preview page is what caught the over-correction in `FL-166`; the
  `/olbg/` write-up for the same fixture had kept the figures and was right.
- **NHL.** The standings payload's own timestamp (`19:29:30Z`) is earlier than the pass clock, so the
  table is a dated input rather than a live claim.
